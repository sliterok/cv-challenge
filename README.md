# Motion3DCaptcha: Dynamic 3D Geometric Captcha Engine

This library is designed to generate highly secure, bot-resistant captchas using **server-side 3D rendering** and **temporal behavior analysis**. Instead of identifying static characters, users must identify a "Target" object based on its unique motion signature in a 3D field.

## ## 1. Core Architecture

The system operates without a browser environment, leveraging native C++ bindings via **`opencv4nodejs`** and **FFmpeg** for high-performance video encoding.

### ### Rendering Pipeline

1. **3D Projection**: Uses `cv.projectPoints` to map 3D vertices  to 2D screen coordinates  using a Pinhole Camera Model.
2. **BGRA Buffering**: Frames are rendered into 4-channel matrices (`cv.CV_8UC4`) to support native transparency.
3. **Video Stream**: Raw pixel data is piped to FFmpeg using the `libvpx-vp9` codec to produce a WebM with an alpha channel.

## ## 2. Security Model: Temporal Distinction

The captcha's primary defense is **temporal analysis**.

* **Noise-Driven Motion**: Every object follows a path generated by Simplex/Perlin noise to ensure smooth, non-linear movement.
* **The Target Identity**: The "Target" object is determined at generation. It is distinguished not by its shape (which may be identical to others) but by a **higher frequency transformation rate**.
* **Transformation Types**:
* **Translation/Rotation**: Moving through 3D space.
* **Morphing**: Real-time jittering of individual vertices in the 3D mesh (shape-shifting).


* **Bot Resistance**: A static classification bot (like a YOLO model) can identify "objects," but it cannot identify the "target" without calculating the delta of motion across multiple frames.

## ## 3. Technical Requirements

To maintain the current Proof of Concept, the following parameters must be strictly followed:

### ### Camera & Visibility

* **Focal Length**: Should be proportional to the width (approx.  width) to maintain a natural field of view.
* **Z-Depth**: Objects must be placed at a depth () where they remain visible within the frustum during noise-based oscillation.

### ### Transparency Setup

The video **must** be transparent to allow for dynamic website backgrounds (preventing pixel-subtraction attacks).

* **Input**: `-pix_fmt bgra`
* **Output**: `-pix_fmt yuva420p`
* **Metadata**: `alpha_mode=1` must be set in the WebM metadata for browser compatibility.

## ## 4. Validation Logic

The backend does not store a single "correct answer" but a **Solution Log**.

1. **Solution Log**: An array of `{ t: timestamp, x: coord, y: coord }` mapped to every frame of the target's center point.
